# Agent 工作约定（入口版）

本文件只负责三件事：

1. 定义本仓库的最终目标；
2. 判断任务先看哪份文档；
3. 约束代码层最基本的检查要求。

细化的 1:1 原型还原规则、页面规格、发布范围、模板和 docs 目录说明全部下沉到 `docs/AGENTS.md`。

---

## 1. 目标

本项目前端默认目标不变：

1. 让 AI 生成的前端代码尽可能稳定地对齐 `ui-prototype demo`；
2. 把“像素级还原”变成可执行、可验证、可回归的工程流程；
3. 让 UI 契约、代码边界、截图回归和协议渲染形成闭环。

---

## 2. 先看哪份文档

### 2.1 按目录分工

| 路径　　　　　　　　　　　　　　　　　　　　　　　　　　 | 类型　　　　　　　　　　　　　　　　　　 | 先看　　　　　　　　　　　|
| ----------------------------------------------------------| ------------------------------------------| ---------------------------|
| `docs/**`　　　　　　　　　　　　　　　　　　　　　　　　| 规范、发布范围、页面规格、模板、设计说明 | `docs/AGENTS.md`　　　　　|
| `skills/**`　　　　　　　　　　　　　　　　　　　　　　　| 本仓库本地 skills 与辅助规则　　　　　　 | `skills/AGENTS.md`　　　　|
| `src/**`　　　　　　　　　　　　　　　　　　　　　　　　 | 前端实现代码　　　　　　　　　　　　　　 | 本文件　　　　　　　　　　|
| `tests/**` / `test-results/**` / `playwright*.config.ts` | 测试、回归、报告　　　　　　　　　　　　 | 本文件 + `docs/AGENTS.md` |
| `scripts/**`　　　　　　　　　　　　　　　　　　　　　　 | 测试/构建/回归脚本　　　　　　　　　　　 | 本文件　　　　　　　　　　|
| `README.md`　　　　　　　　　　　　　　　　　　　　　　　| 人类导航　　　　　　　　　　　　　　　　 | 不作为正式执行依据　　　　|

### 2.2 路由规则

1. 只改 `docs/**`：先读 `docs/AGENTS.md`。
2. 只改 `skills/**`：先读 `skills/AGENTS.md`。
3. 改 `src/**`、`tests/**`、`scripts/**`：先读本文件；若任务涉及 UI、原型、截图、页面规格或发布范围，再补读 `docs/AGENTS.md`。
4. 同时改代码和 docs：两边规则都生效；文档负责正式规则，代码负责实现与验证。

---

## 3. 任务分类

### 3.1 像素级还原任务

需求中出现以下任一语义，按像素级任务处理：

1. “对齐原型”
2. “对齐截图”
3. “1:1 还原”
4. “像素级还原”
5. “按 demo 做”

像素级任务必须进入 `docs/AGENTS.md` 里的页面规格和截图回归流程。

### 3.2 常规 UI / 工程任务

没有明确要求对齐原型，只要求维护、重构、补交互、修测试、修协议时，按常规任务处理。  
常规任务依然要遵守分层、i18n、验证要求和已存在的页面规格。

---

## 4. 简单改动和需要慎重处理的改动

### 4.1 简单改动

满足以下条件时，可以只读对应入口文件与实际改动文件：

1. 明确文件路径的小范围文本修正；
2. 不改变发布范围、页面规格、契约优先级、对外说法；
3. 不新增第二套正式依据。

### 4.2 需要慎重处理的改动

命中以下任一条件时，必须通读对应入口规则并谨慎收口：

1. 修改 `AGENTS.md`、目录边界、规则优先级或检查要求；
2. 修改 `docs/发布范围/**`、`docs/页面规格/**`、`docs/规格模板/**`；
3. 修改视觉回归入口、阈值、截图区域或对外“1:1 完成”的说法；
4. 新增会影响 AI 决策的新正式规则入口。

---

## 5. 代码硬约束

### 5.1 分层边界

1. `pages` 只做路由级容器编排，不直接做裸请求与协议转换。
2. `components` 只做渲染与交互，不直接消费后端原始响应。
3. `store` 负责异步流程编排与跨组件状态，不返回 JSX。
4. `services` 负责 API 调用、协议适配、错误归一化，不持有 UI 状态。

### 5.2 前端实现

1. 颜色、字号、圆角、阴影、间距优先复用 token 和共享组件。
2. 前端文案必须走 i18n，默认语言为英文。
3. 协议渲染不得猜字段；消息、富内容、思考态遵循既有契约。
4. 未在页面规格、契约或 token 中登记的视觉值，不应直接写入业务代码。

### 5.3 提交前检查

至少完成以下检查：

1. `npm run build`
2. `npm run test`
3. 受影响模块测试通过
4. 如果任务涉及像素级页面，跑对应截图回归
5. 如果任务涉及消息/事件渲染，补协议回放或等价验证

---

## 6. 重点检查

1. 发现 P0 / P1 / P2 问题且可安全修复时，先修再交付。
2. 缺用户事实、缺原型状态、缺页面规格、缺发布范围时，不得硬宣称完成。
3. 未关闭项只能是用户明确接受的风险，或低优先级后续项。

---

## 7. 交付说明

每次 UI / 工程改动都至少说明：

1. 改了什么；
2. 契约对照；
3. 验证结果；
4. 风险与后续建议。
