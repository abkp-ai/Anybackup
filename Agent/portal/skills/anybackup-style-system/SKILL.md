# Anybackup 样式系统

在 `当前仓库` 处理前端样式、布局或视觉决策时，使用本技能把实现对齐到已确认的 Anybackup 产品体验体系。

## 资料来源与优先级

修改 UI 前，按下面顺序理解约束：

1. `../../docs/V9用户体验体系规范.md`
   作用：总的体验原则、视觉基线、token 方向。
2. `../../docs/V1对话流程-前端样式实现基线.md`
   作用：V1 当前项目的工程化样式映射。
3. `../../../ui-prototype`
   作用：具体页面结构、尺寸、交互和视觉落点。
4. `../../src`
   作用：当前项目的公共组件、token 和工程实现边界。

如果任务同时涉及需求、原型和实现，请配合 `product-context` 一起使用。

## 三层依据

以后做样式决策，按这三层理解：

1. `V9` 决定方向
   内容包括：气质、原则、颜色语义、圆角等级、阴影、动效基线。
2. `ui-prototype` 决定落点
   内容包括：具体页面怎么排、输入框多高、标题多大、按钮位置、菜单交互。
3. `web_app_agent` 当前代码决定落地方式
   内容包括：复用哪些公共组件、哪些 token 已存在、哪些改动应该收进公共层。

一句话：

**V9 是总依据，原型是页面依据，当前项目代码是工程依据。**

## 冲突处理

如果三者冲突，按下面规则处理：

1. 功能范围以需求为准。
2. 页面结构、交互、尺寸和视觉细节以原型为准。
3. 工程实现方式优先复用当前项目已有公共组件和 token。
4. 不要因为复用方便，就让页面偏离原型。
5. 不要因为追原型像素复刻，就绕开当前项目的公共样式体系。

## 执行流程

1. 先判断当前改的是哪一类界面：
   - 登录页
   - 应用侧边栏
   - 会话侧边栏
   - 对话区
   - 空白会话态
   - 错误/等待/重试状态
   - 设置页
   - 用户管理
2. 阅读 `V1对话流程-前端样式实现基线.md` 对应章节。
3. 对照 `ui-prototype` 里的同位置组件，确认：
   - 宽度
   - 高度
   - 圆角
   - 字号
   - 间距
   - hover / active / disabled
   - 错误 / 空态 / loading
4. 再检查当前项目里是否已有可复用的：
   - `src/index.css`
   - `tailwind.config.ts`
   - `src/components/ui`
   - 已有页面壳层组件
5. 优先通过 token 和公共组件落地，不在业务组件里临时发明视觉体系。
6. 改完后按本技能的“快速检查”再过一遍。

## 设计规则

- 保持“友好、极简、现代、AI 原生”的视觉语言。
- 颜色、圆角、阴影、字体、间距、状态和 AI 表现必须优先使用语义 token。
- 不在业务组件里散落硬编码颜色、阴影、圆角或一次性渐变。
- V1 不引入审批、执行、CLI 或 RBAC 等范围外视觉概念。
- 不要把整个应用、主工作台或对话主区域包进装饰性大卡片。
- 卡片只用于真实内容单元，例如摘要、用户行、对话框和结构化结果。

## 原型对齐规则

### 1. 先对齐壳层，再对齐内容卡片

优先收这些基础区域：

1. 侧栏宽度
2. 新建会话按钮
3. 搜索框
4. 历史会话列表项
5. 空白会话态
6. 输入框
7. 模态框

不要一上来先雕候选方案卡片、复杂富内容组件。

### 2. 默认不要“卡片化过度”

原型整体是轻量、紧凑、克制的，不是满屏大卡片。

避免：

1. 大面积 `rounded-2xl / rounded-3xl`
2. 很厚的阴影
3. 很重的边框
4. 很大的容器 padding
5. 组件之间过松的留白

### 3. 圆角按三级使用

默认按下面三档控制：

1. `rounded-sm`
   用于：小按钮、搜索框、小触发器。
2. `rounded-md`
   用于：输入框、表单项、普通按钮、普通列表项。
3. `rounded-lg / rounded-xl`
   用于：模态框、主要卡片、聊天状态容器。

除非原型明确如此，否则不要随手上 `rounded-2xl`。

### 4. 输入框要“薄”，不要“鼓”

输入框是最容易把页面气质带偏的地方。

优先保证：

1. 高度适中
2. 圆角克制
3. 内边距紧凑
4. 阴影轻
5. placeholder 不抢内容

判断标准：

**更像工作台输入器，而不是营销页搜索框。**

### 5. 字号先收小一档再判断

如果一个页面看起来“不像原型”，很大概率不是颜色问题，而是字太大。

优先检查：

1. 空白态标题是不是过大
2. 描述文案是不是太长太显眼
3. 列表项字号是不是偏大
4. 辅助文案是不是抢主信息

默认倾向：

1. 标题更短
2. 正文更稳
3. 辅助文字更轻

### 6. 图标、按钮、头像必须共用同一套 AI 视觉

下面这些元素必须统一来源：

1. 发送按钮
2. 用户头像
3. AI 图标
4. 高亮状态按钮

优先复用统一的 `ai` 按钮和渐变定义，不要组件内临时拼颜色。

### 7. 原型是“密度参考”，不是“像素复刻”

我们要对齐的是：

1. 视觉气质
2. 信息层级
3. 交互节奏
4. 密度和克制感

不是要求把原型每个像素、每个 DOM 原样搬过来。

## 必选样式

除非原型或需求明确说明，否则默认采用：

| 范围 | 选择 |
| --- | --- |
| 颜色 | HSL CSS 变量和 Tailwind 语义 token |
| 主操作 | `--primary` / `bg-primary`，用于发送、确认、用户消息 |
| AI 视觉 | `--ai`、`--ai-surface`、`--ai-glow`、`--ai-purple` |
| 状态语义 | `success`、`warning`、`destructive`、`muted` |
| 圆角 | 徽章 6px；按钮/输入/导航/普通卡片 8-10px；对话状态容器/主要卡片 12-16px |
| 字体 | Inter + 中文系统字体栈，默认正文 14px |
| 间距 | 4px 基线，页面内容区域通常 24px |
| 动效 | 只使用 transform、opacity、filter，并支持 `prefers-reduced-motion` |
| 焦点 | 输入框、按钮、菜单和图标按钮必须有可见焦点态 |

## 界面指引

### 登录页

- 保持与原型一致的品牌感和克制背景。
- 错误信息显示在表单内部，不用浏览器弹窗。
- 表单不要做成过厚的大圆角卡片。

### 应用侧边栏

- Logo、产品名、导航、底部用户区遵循原型布局。
- 状态切换不能造成明显跳动。
- 不要把每个导航项都做成大卡片。

### 会话侧边栏

- 强调会话管理，不表现为审批管理。
- 新建会话、搜索、历史列表项优先按原型尺寸实现。
- 列表使用紧凑、稳定的行高和轻 hover，不做厚卡片堆叠。

### 对话区

- 用户消息靠右，Agent 消息靠左。
- 空白态只保留必要的信息层级，不做营销式 Hero。
- 输入框保持原型的紧凑高度和克制圆角。
- 错误、loading、重试优先做页面内轻反馈，不做压迫感横幅。

### 用户管理

- 复用统一按钮、输入框、状态徽章、模态框和表格基线。
- 字段错误优先显示在字段下方，不放大成页面级提示。
- 即时反馈使用非阻塞轻提示，并在 3 到 5 秒内自动消失。

## 快速检查

每次改 UI 前后，都先过这 8 个问题：

1. 这次改的是壳层，还是内容组件？
2. 有没有先看原型里同位置组件的高度、圆角、字号？
3. 有没有直接复用项目已有 token 和公共组件？
4. 当前视觉是不是比原型更厚、更圆、更松？
5. 这个组件是不是被我做得太像独立卡片了？
6. 输入框、按钮、列表项是不是大了一档？
7. 辅助说明是不是过多、过重？
8. 如果把阴影减半、圆角减一档、padding 收一点，会不会更像原型？

如果其中 3 条以上答案是“会”，就先收视觉再继续。

## 一句话执行原则

以后在这个项目里做 UI，如果拿不准，就先选这条：

**更轻一点、更小一点、更紧一点、更像工作台一点。**
